## 📤 Output Format

You must respond with a **single valid JSON object**. It is CRITICAL that you generate the `description` field FIRST to reason before acting:

```json
{
  "description": "Step 0: MULTIPLE DOORS — Are there multiple open voids? If yes, I MUST identify which one is the target room using visual clues (e.g., checkered floor = bathroom, bed = bedroom) and IGNORE the others. Step 1: POSITION — Where is the TARGET door? (left, right, or center). Step 2: ROUGH CENTERING — If the target door is left or right, I MUST apply Rule 1 and ROTATE (Left=B, Right=C). I will not evaluate angles until it is centered. Step 3: DIAGONAL CHECK — If the door IS roughly centered, I will check the frame edges. LEFT edge: [VISIBLE/NOT VISIBLE]? RIGHT edge: [VISIBLE/NOT VISIBLE]? If only one edge is visible, I am diagonal and must apply Rule 3 (Slide D1/D2). Step 4: Final command decision.",
  "door_position": "left | center | right | not_visible",
  "door_angle": "perpendicular | diagonal_from_left | diagonal_from_right | unknown",
  "room": "estimated_room_name_or_unknown",
  "state": "next_FSM_state",
  "movement": "valid_single_movement_command",
  "memory_update": "..."
}
```

✅ Field Definitions

- `"description"`: Detailed reasoning. You MUST use keywords like `'closed'`, `'cabinet'`, `'open void'`, `'wall'` when applicable. The movement chosen must follow from this reasoning.

- `"door_position"`: Horizontal position of the candidate door opening in the image. Valid values: `"left"`, `"center"`, `"right"`, `"not_visible"`. This answers: WHERE is the door in the frame?

- `"door_angle"`: Perpendicularity assessment. Valid values:
  - `"perpendicular"`: Both doorframe posts are flat vertical lines, no inner depth visible. You are aligned at 0°.
  - `"diagonal_from_left"`: You are offset to the LEFT of the door. Evidence: large wall on the left + only left frame edge visible, OR right frame inner depth visible at close range.
  - `"diagonal_from_right"`: You are offset to the RIGHT of the door. Evidence: large wall on the right + only right frame edge visible, OR left frame inner depth visible at close range.
  - `"unknown"`: Both frames visible but too far to judge inner depth detail, or no door visible.
  **KEY: You do NOT need to be close to set this field.** If you can only see ONE doorframe edge and the other side is wall, that IS enough to determine the angle. Only use `"unknown"` when BOTH edges are visible but detail is insufficient.

- `"room"`: Current room from topological map, or `"unknown"`.

- `"state"`: Next FSM state.

- `"movement"`: Single command (A1, B1, etc.) chosen AFTER reasoning.

- `"memory_update"`: A short note (max 200 chars) to your future self. Record landmarks, ignored doors, recognized rooms, obstacles, or any observation that will prevent you from repeating mistakes or re-exploring areas. If you receive an `Agent Memory` input, read it before deciding — it contains your notes from previous steps. If nothing new happened, copy the previous memory verbatim.

⚠️ Important

- Do not add extra text or explanations outside the JSON block.
- Always follow the allowed command list and transition logic defined in the state prompt.
- Use all available context (image, state, previous movement, user query, and map) to ensure safe and meaningful output.
